# Phase 3 预备任务书：反作弊专用极简 Windows Guest 优化器

日期：2026-11-22
状态：**预备（待 Phase 2 干净基线跑通后启动；不打断当前 Phase 2 四个并行窗口）**
前置依赖：
- Phase 2 窗口 A 交付干净官方基线下的 Guest 启动耗时、空载内存、CPU 与磁盘占用数据；
- Phase 2 窗口 B 交付自有内核探针实测报告及目标反作弊驱动架构/完整性硬依赖清单。

---

## 1. 核心目标

在 **不破坏 Windows 内核、官方代码签名链与反作弊必需的完整性依赖** 的前提下，构建一套**自动化、可回滚、可量化的「反作弊专用极简 Windows Guest 优化器」**，尽量砍掉所有与反作弊和游戏运行无关的完整桌面系统框架与后台开销，将 Guest 宿主机资源消耗压到最低。

> 架构分工原则不变：
> - **无内核反作弊的普通 Windows 游戏**：继续走 Wine（DXVK / D3DMetal），零 Windows OS 框架开销。
> - **必须依赖真实 Windows 内核的场景**：走本 Phase 3 产出的极简 Guest 运行环境。

---

## 2. 三层裁剪方案（必须分层验证、逐项可回滚）

### 层一：合规轻量 OS 底座选型（严禁第三方魔改破签 ISO）
- 以 Phase 2 的标准官方 **Windows 11 24H2+ ARM64**（内置支持 AVX/AVX2 的新版 Prism 引擎）为对照组，评估微软官方精简通道（如 **Windows 11 24H2+ Enterprise LTSC / IoT** 官方镜像）的资源基线差异。
- 所有底座必须保留正规授权与完整系统文件签名（`SFC` / Code Integrity 正常），禁止使用破坏签名链的民间魔改版（如 Tiny11）。

### 层二：Guest 内「反作弊极简优化器」（声明式裁剪与白名单保护）
实现一套配置驱动（JSON Profile + 幂等 PowerShell / 离线映像配置脚本）的优化器，严格区分**不可动白名单**与**按需裁剪清单**：

1. **强制保留白名单（严禁裁剪）**：
   - Windows 内核、HAL、代码完整性校验（CI.dll / CryptSvc / 证书与根信任链）；
   - **Windows 11 24H2+ `Prism`（AVX/AVX2）转译引擎与 `Arm64X / Arm64EC` 用户态兼容运行时**（支撑“x64 游戏本体 + 原生 ARM64 反作弊驱动”混合执行模式）；
   - 安全与完整性链路（TPM / Secure Boot / HVCI / 反作弊明确依赖的 Windows 安全子系统与内核服务）；
   - 目标反作弊驱动（首要焦点 VALORANT 对应的 ACE / Vanguard）及服务运行链、必要 D3D / Visual C++ / 音频 / 网络基础协议栈；
   - Guest Agent 与宿主通信/共享目录映射通道。
2. **反作弊不需要的内容（最大化裁剪目标）**：
   - **消费级预装与 UWP 组件**：Edge、Microsoft Store、Widgets、Copilot、OneDrive、Teams、Xbox 非必要叠层、自带娱乐/办公应用；
   - **重型常驻后台服务**：Windows Search 索引、SysMain、打印/传真（Spooler）、蓝牙、生物识别、地理定位、遥测与诊断追踪（DiagTrack）、非游戏期自动后台更新（会话期暂停）；
   - **图形与桌面外壳减负**：关闭桌面透明/动画/合成特效，并重点验证 **极简 Shell / 无完整 Explorer 桌面直启模式**（在满足游戏窗口与反作弊前置校验的前提下，最小化桌面常驻内存与 DWM 开销）。
3. **自动回滚机制**：优化器每次执行前生成可逆状态快照/服务初始状态记录，支持一键恢复默认配置。

### 层三：宿主虚拟化层减负 + 开源 WDDM 3D 零拷贝卸载
- 以 Phase 2 的 UTM/QEMU 后端为基线，评估基于 **Apple 原生 `Virtualization.framework`（纯 Swift 轻量 VMM）** 的替代后端：
  - 砍掉非必要虚拟硬件设备（冗余 USB 控制器、摄像头、蓝牙、多余串口等）；
  - 仅保留最小设备树（VirtIO 块设备、网络、VirtioFS 共享目录、vsock/Agent 通道及必要显示/图形卸载路径）；
  - 实现按需冷/热拉起与退出即彻底释放宿主内存（闲置时常驻开销为 0）。
- **Guest 图形卸载正式底座（不重造轮子，告别 TCP 像素回读）**：
  - 评估复用开源 **`virtio-gpu` WDDM 3D 驱动（`viogpu3d.sys`）+ Apple `Virtualization.framework` 共享内存环形缓冲 / 命令流直通宿主 Metal（Metal 4 / MetalFX）**；
  - 严格走操作系统正规签名显卡驱动栈（不向受保护游戏进程注入用户态代理 DLL），并核查微软 WHQL 签名状态与 DX11/DX12 成熟度。

### 层四：强硬件信任根反作弊的合规兜底后端（架构预留）
- 针对明确禁止 Hypervisor 或强制要求物理 TPM 2.0 芯片背书证书（Hardware Root of Trust）的商业游戏（本地任意 VM 在合规前提下均无法绕过）：
  - 在 `RuntimeCoordinator` 中预留第三类执行后端 **`RemotePhysicsBackend`**（统一调度本地 Wine 三引擎 / 本地极简 Guest / 局域网副机或合规 x86 物理云机低延迟串流，如 Sunshine/Moonlight 协议级集成），使整套应用在不触碰反作弊红线前提下实现全场景闭环。

## 3. 量化验收红线（以数据说话）

优化器每一层改动都必须与 **Phase 2 干净官方基线** 在同硬件、同配额、同场景下做配对对比，并绑定源码/脚本/镜像版本摘要：

| 验收维度 | 必须记录的量化指标 |
| --- | --- |
| **资源削减** | 虚拟盘实际占用（GiB）、冷/热启动至 Agent 就绪耗时（s）、空载常驻内存（MiB）、空载宿主 CPU（%）、运行测试负载时的内存与帧时间抖动 |
| **完整性与探针回归** | `ModuleAProbe` 全生命周期探针 100% 通过、系统代码完整性/签名校验无异常 |
| **反作弊兼容性** | 首要回归焦点为 **VALORANT**（并可辅以已上线原生 ARM64 驱动的 EAC/BattlEye 对照试金石验证 `Prism + 原生 ARM64 驱动 + viogpu3d` 链路）；若某项裁剪导致新增拒绝/错误码，自动标记该组件进入「强制保留白名单」并回滚，绝不强砍 |

## 4. 合规与工程红线

1. 任何精简操作仅限于关闭/移除反作弊与游戏不需要的系统冗余组件，**严禁伪造硬件标识、篡改反作弊驱动或绕过完整性检测**。
2. 未经实测验证不得宣称“性能提升 X%”或“兼容某商业反作弊”。
3. 交付物包括：可复现裁剪 Profile、幂等优化与一键回滚脚本、分层对比实测报告（脱敏）及更新后的最小设备树 VMM 评估结论。
