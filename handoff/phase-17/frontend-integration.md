# 后端接口与并行前端对接

日期：2026-11-26  
维护：@DNPMBHC

本轮保留现有前端结构，下面接口供并行前端接入。接口测试通过不等于前端已经接通。

## 安装后入口发现与登记

主线程调用 orchestrator：

- discoverInstalledGameCandidates(for:query:) async throws -> [InstalledGameCandidate]
- registerInstalledGame(_:candidate:) async throws -> UnifiedGameEntry

候选包含 name、executablePath、arguments、workingDirectory、vmIdentifier 和稳定 id。目前扫描当前容器的系统开始菜单及已登录用户默认个人开始菜单，读取匹配名称的快捷方式元数据，不执行快捷方式，不执行卸载命令，不遍历所有磁盘。未覆盖自定义已知文件夹重定向及没有快捷方式的安装方式。

建议在安装流程结束或用户返回应用后提供“扫描游戏入口”，允许修改搜索名称。扫描要求所选 Windows 已启动、登录且来宾工具可用；不会替用户启动或安装系统。空结果应提供重试、修改关键词及现有手动入口选择。多个结果需要用户消歧，不能自动选第一个。

用户确认后调用登记接口。后端会重新核验同一个容器内的真实 exe 存在、保留启动参数与工作目录，并核验游戏库落盘。失败、取消、跨容器候选、已变更条目或无法保存均不将安装标为完成。

installationState = .installerRequested 仍只表示安装器启动请求，不能提前设为 ready。候选扫描成功也不等于安装完成、反作弊可用或匹配可玩。不要通过直接修改模型跳过登记核验。

模型新增可选 launchArguments、launchWorkingDirectory，旧 JSON 缺少这些字段时仍可读取。不要在错误报告中上传程序路径、快捷方式参数或用户标识。

## 窗口与原生网络

窗口会话桥接已在统一启动器接线，测试覆盖随机会话、容器身份、进程创建时间、前台 PID、信号新鲜度与旧任务隔离；不使用全局广播。原生服务诊断已实现 15 秒就绪期限，最终通过项见 verification.md。安装器或普通 launcher 的 PID 回执不能单独触发“游戏已就绪”。受限的前台证明无法确认 launcher 派生游戏进程时，应保留现有窗口，而不伪报游戏前台。

原生网络的批准入口继续沿用第 16 阶段接口。系统批准、服务入口就绪、实例网络配置和真实联网是独立状态。获准但长期未就绪时应展示可操作超时反馈；恢复后重读真实状态。当前界面只在进入、应用激活或手动刷新时读取；前端应在 starting 状态有界轮询（例如每秒一次），离开等待状态或视图销毁后停止，才能自动呈现期限错误。不要把 socket 存在展示为游戏已经联网，也不要显示尚未集成的用户态代理已启用。

## 自动部署的后续接口边界

尚无从零安装 Windows、合法授权、来宾工具安装与重启恢复的一体化接口。首次配置不能将“组件已打包”显示为“系统环境已准备完毕”。针对已有国服成功环境继续提取可复现配置，先完成受管工作副本、分步回执和恢复，再扩展其他游戏目标。
