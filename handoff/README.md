# 并行任务总表

日期：2026-11-21。仓库统一代称 my-project，模块代称仅用于任务分工。

目标：在 macOS 上提高 Windows 游戏运行效率，核心先验证真实反作弊驱动与游戏进程的兼容性，再优化虚拟化与图形路径。性能提升和具体游戏在线可用性均需实测。

## 第一优先级

module-a 是反作弊内核适配，属于 P0。需要验证的结果是：真实 Windows 内核能够运行相应架构、合法签名的驱动，驱动实际看到并保护游戏所在的进程与内存，启动环境满足真实完整性要求。程序名称识别、成功启动 guest、服务处于运行状态，都不能单独作为适配成功的证据。

设计基线分两条路径：

- 路径 A：游戏和反作弊位于同一个 Windows guest，研究图形与呈现向 macOS 后端卸载的性能空间。
- 路径 B：游戏在 Wine，反作弊跨 guest 观测。这是一条需要厂商提供跨边界接口与支持的合作研究路径；在获得接口并验证前，保留研究状态，不作为已实现功能。

Windows 内核执行、CPU 指令转译、图形 API 转译分别建模；用户态程序能够转译执行，不能据此推定其内核驱动能够运行。研究时必须核实宿主 CPU、guest CPU 及驱动架构。
