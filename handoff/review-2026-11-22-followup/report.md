## 本轮发现

### R1 / P1 / A：根启动器退出会终止下载或游戏子进程

审查版 desktop-helper.cpp 第 384–388 行创建带 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE 的 Job，第 516–522 行在根进程退出后立即关闭该 Job。bootstrap 或 launcher 拉起 downloader/game 后正常退出，会导致仍运行的后代被终止。

需要区分根进程退出、任务树仍运行、任务树完成和取消/故障。保持可追踪的 Job 生命周期或实现明确的正常移交；取消与故障才终止任务树。验收必须覆盖父启动器 exit 0 后子进程继续运行、输出可追踪、取消可终止并确认清理的路径。

状态：已反馈，A 随后修改了 helper：新增根进程退出和 Job 活跃进程计数，任务树清零后才关闭 Job。复审确认 controller 保留真实根 HANDLE 并接受根已退出而子进程仍活跃，宿主会话新字段也已贯通。源码修复通过复审；真实 bootstrap 验收仍未完成。最初发现与后续源码修复分别绑定指纹，不能把源码修正当作真实安装验证。

### R2 / P2 / A：底层自动化调用不能被外层期限打断

审查版宿主 transport 第 102–120 行通过 detached task 执行 osascript，阻塞读输出并等待退出，没有进程级 deadline 或取消处理。桌面层的轮询期限无法中断已经卡住的自动化调用。

需要让底层进程 runner 接收 deadline 和 cancellation，超时或取消后终止并回收本次宿主子进程，同时保留 Guest 目标的独立清理状态。建议用自有挂起进程验证，避免用真实游戏复现。

状态：已反馈；控制流缺口已确认，尚未做挂起进程复现。

### R3 / P2 / C：FPS 比较采用不同的完成边界

审查版 analyze.py 第 162、201 行只由 cpu_frame_ms 均值推导 FPS。Direct 在 Present(0,0) 返回后继续；command-only 每帧等待宿主 GPU 完成 ACK。Direct 整轮末尾的 GPU drain 没有进入这个派生 FPS，流水线深度也不同。

可以明确比较提交/ACK 吞吐量，或者统一完成边界和允许的流水线深度后重测。GPU command complete、交换链提交与实际屏幕呈现应分别命名。最新宿主遥测已增加 gpu-command-complete 的完成范围字段。

状态：已反馈；本轮没有发现新增实测数字被虚报，问题在当前统计口径。

### R4 / P2 / C：正确性捕获可能影响性能统计

当前探针允许在测量区捕获，复制、Map 和写盘可能进入帧时间；现有分析器不识别或剔除 capture 帧。新编排正在开发，尚未完成该方面的验收。

建议将像素正确性捕获和无捕获性能运行分开；若混合运行，则 CSV、manifest 和分析器都要记录并严格排除捕获帧。

状态：已反馈，为当前待验收风险；不能据此断言尚未完成的新编排一定存在最终缺陷。

### R5 / P2 / A：取消存活子进程可能被报告为成功退出

R1 修复后，根进程先 exit 0、子进程仍活跃时，取消可以终止任务树，但 helper 会话 exitCode 仍沿用根进程的 0。宿主模型强制会话退出码等于根退出码，wait 忽略 cancelled 并返回成功退出。

需要独立保留 rootExitCode 与会话终态，让取消明确传播给调用者。必须补充根进程 exit 0 后取消存活子进程的测试，同时验证任务树已清理。

状态：已反馈；静态复审已确认，真实 Guest 取消仍待验证。
