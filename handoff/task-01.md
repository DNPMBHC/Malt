# 任务 01：反作弊内核适配（module-a，P0）

这是核心任务，优先于界面与性能包装。请先阅读 handoff/README.md，并接续现有未提交基线。

## 目标与范围

建立真实 Windows 内核驱动运行与保护范围的可验证原型。首轮分别核实 VALORANT、League of Legends Windows 客户端、THE FINALS 使用的驱动架构、系统要求及受支持执行环境，证据由 06 协同提供。

与 02 一起确认 Windows guest 的内核、guest CPU 架构和普通进程运行路径。检查驱动二进制的机器架构、合法签名与实际加载结果；区分用户态兼容能力与内核态能力。

先用自有、合法签名、无侵入功能的诊断驱动和测试进程验证：服务加载、实际进程对象、文档化进程通知、请求/响应、正常卸载及重启后的状态。该探针用于证明执行环境，不能代表商业反作弊已适配。

对真实厂商组件，只使用厂商提供的安装与诊断路径记录兼容结果；厂商支持结论由 06 核验。测试环境与真实游戏环境分别记录。

## 两条架构研究线

A. 游戏逻辑与反作弊在同一 Windows guest，图形卸载由 03 提供。这是首个需要实现并验证的原型。

B. 游戏在 Wine、驱动在 guest。先定义进程与地址空间、模块生命周期、内存一致性、事件顺序、信任与认证需求。只有存在厂商支持的跨边界接口才能进入商业组件集成；没有接口时交付缺口清单和可复现的自有程序实验。

原型保持平台真实身份和真实完整性状态，记录实际拒绝与错误；不将伪造硬件、修改保护组件或隐瞒虚拟化作为兼容实现。

## 交付

- 驱动/guest/宿主架构矩阵及官方证据。
- 自有诊断驱动、测试进程及可重复运行说明，源码和必要许可信息齐全。
- 驱动加载与保护范围探测接口，输出结构化状态给 05。
- 路径 A 的实际验证报告；路径 B 的接口依赖、实验和阻塞。
- 对每款游戏分别标记：未验证、架构阻塞、环境不支持、等待厂商支持或实测通过。

## 验收

能证明驱动看到的是实际执行测试负载的进程；正常及失败路径均可复现。驱动启动不等于保护有效，自有探针通过不等于商业反作弊通过，guest 启动不等于游戏在线可用。

## 当前实现状态

自有探针已实现：固定协议 ABI（当前版本 2）、报告 schema（当前版本 2）、候选驱动架构与 Authenticode 报告、服务生命周期脚本、实际请求进程对象比较、常驻进程创建通知、暂停子进程 PID 绑定、驱动回传 PID 确认，以及创建/退出状态查询。PID 候选只在驱动内存中短期保存，绑定成功后立即移除；采集器只有在确认驱动回传 PID 与 CreateProcessW 返回值一致后才恢复子进程；查询与 disarm 使用 rundown 和状态锁取得一致快照；客户端额外报告子进程句柄是否已变为有信号状态，未完成回收或绑定证据缺失不会计入成功。探针不读取或写入目标进程内存，也不模拟厂商反作弊协议。

本机 ABI CTest 通过 1/1。任务07最新冻结门禁记录91项总数、90项通过、1项可选A/B跳过，失败/错误为0（MTL_DEBUG_LAYER=1）；旧77项属于历史快照。最新CLI合成存储预检通过，不能证明真实驱动或guest保护。PowerShell 生命周期脚本已加强 JSON 必需字段及布尔/字符串类型检查，但当前主机没有 PowerShell，尚未执行脚本。WDK 驱动编译、签名、加载/卸载、重启持久性、并发压力和真实厂商组件或游戏验证仍需在匹配的 Windows guest 中完成。

## 协作边界

与 02 共同调试 guest；向 03 提供保护范围约束；共享模型变更交给 05。公共模块中不加入真实游戏组件的私有协议模拟。
