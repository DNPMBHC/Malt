# 任务 03：图形卸载与转译性能（module-c，P1）

请先阅读 handoff/README.md。目标是比较可实现的高效路径，并用实际数据选择。

## 两个原型

1. Wine 图形路径：比较当前已有的公开转译后端，维护可重复的冷启动、着色器预热与稳态性能基线。
2. Windows guest 图形路径：在 02 的普通测试程序上验证 guest 到宿主的图形传输与呈现方案。先测试低频命令、批处理、资源传输与 fence，再讨论进一步减少拷贝。

Windows 用户态程序的 D3D 转译器不能直接等同于虚拟 GPU 驱动。原型需要明确 API 层、设备层、资源所有权、同步与实际落地方式。每个阶段标出已实现部分和仍需要驱动/厂商接口的部分。

## 与内核任务协作

游戏逻辑和反作弊的执行域由 01/02 决定。图形资源在宿主上呈现时，需要与 01 一起定义保护范围和可信边界；不能把 Wine 中的普通进程描述为 guest 的真实进程。

## 交付与验收

自有 D3D 测试程序、一个能运行的图形路径实验、CPU/GPU 时间与每帧传输统计、资源生命周期及故障恢复说明。

任务 07 的最终集成门禁必须在 macOS 上运行 `graphics-lab` 测试发现命令 `python3 -B -m unittest discover -v`，并单列验收 `test_metalfx_sdk_compile.py` 对当前 macOS SDK 的类型检查结果。若该测试因平台或 SDK 缺失而跳过，应记录为未验证，不计为通过。

比较平均帧率、P95/P99 帧时间、输入到呈现延迟、内存、帧传输量、功耗和温度；固定分辨率、画质、负载、系统及后端版本。没有真实数据不得宣称显著提升。

## 文件归属

独立图形实验、协议与基准工具。共享宿主能力来自 04，接口变化由 05 统筹。
